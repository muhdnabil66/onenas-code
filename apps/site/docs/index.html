Documentation

Build locally with AtlasFlux intelligence.

ONeNas Code is a local-first coding agent. Your terminal, project files and tool execution stay on your computer while AtlasFlux AI provides identity, model access, policy and account credits.

Install

Install the latest CLI globally with npm:

npm i -g onenas-code

Start it from any project folder:

cd path/to/your-project
onenas

On first launch, a browser window opens for AtlasFlux authorization. After login, return to the terminal and ONeNas Code starts the agent.

Core Features

Local workspace

Open any folder and let the agent read files, edit code, inspect diffs and run commands directly in that workspace.

Agent workflows

Use planning, implementation, review, subagents, task tracking and automatic context management for multi-step work.

Terminal tools

Run shell commands with permission controls, inspect output, and keep command activity visible in the session timeline.

Git-aware sessions

Review changes, inspect branches and diffs, create commits, work with pull requests and keep coding sessions organized.

MCP and skills

Connect MCP servers and install reusable skills or commands to extend the agent with project-specific workflows.

LSP and formatters

Use configured language servers and formatters for navigation, diagnostics, symbol search and consistent code style.

Sessions and resume

Continue previous sessions, switch projects, inspect history and recover context without leaving your local workspace.

Desktop and CLI

Use the Windows desktop experience or the npm CLI against the same local-first ONeNas Code workflow.

AtlasFlux Account

These commands are available in PowerShell or any supported terminal:

onenas login       # Sign in to AtlasFlux AI
onenas account     # Show profile, plan, credits and models
onenas balance     # Show credits and plan
onenas sync        # Refresh account and model data
onenas logout      # Remove the local AtlasFlux session

Inside the TUI, the same account tools are available as slash commands:

/account
/balance
/sync

Providers and Models

AtlasFlux is the default provider for ONeNas Code. The provider catalog also supports direct connections to configured providers such as OpenAI, Anthropic, Google, OpenRouter, xAI, Groq, Mistral, NVIDIA, GitHub Copilot and many others.

The removed opencode provider and its hosted infrastructure are not part of ONeNas Code. Direct provider connections use the provider's own API endpoint and credentials.

ILMU API

ILMU is available as an OpenAI-compatible provider hosted by YTL AI Labs in Malaysia. Configure its API key before selecting an ILMU model: 

$env:ILMU_API_KEY = "sk-your-ilmu-key"
onenas

Start the TUI, open the model picker, and choose an ILMU model. The CLI onenas models command shows AtlasFlux-managed account models; configured third-party providers are selected from the TUI model picker.

ILMU uses https://api.ilmu.ai/v1 and includes models such as ilmu-v3.1, ilmu-mini-v3.3, nemo-super and ilmu-nemo-nano.

Themes

Open the theme picker from the TUI with the theme shortcut, then select:

  • onenas alpha - red theme using #FF3333, enabled by default.
  • onenas myra - pink theme using #FF1493.

Each ONeNas theme defines the complete interface palette: background, panels, text, borders, status colors, diffs, markdown and syntax highlighting.

Configuration

ONeNas Code supports onenas.json and onenas.jsonc. Existing opencode.json files remain readable for migration. The TUI looks for local configuration and commands in the project folder and global configuration under the ONeNas data directories.

Provider credentials can be supplied through environment variables, the provider login flow, or provider configuration. Keep API keys out of source control.

Privacy Boundary

Project files, terminal execution and local sessions remain on the machine. AtlasFlux handles authentication, model routing, policy and credits. Prompts and assistant responses may be sent to the selected model provider so the agent can answer; provider privacy policies and your configuration determine the external processing boundary.

When AtlasFlux is unavailable, local files and existing sessions remain inspectable, but new AtlasFlux-managed AI runs cannot start.

Troubleshooting

  • Browser login does not open: run onenas login again and use the printed authorization URL as a fallback.
  • Provider is not listed: configure its API key, then restart ONeNas Code and run onenas models <provider>.
  • AtlasFlux token expired: run onenas login to authorize again.
  • Wrong default model: select an AtlasFlux model in the model picker or keep the managed AtlasFlux configuration enabled.
